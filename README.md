# Text-Mediated First-Person LLM Navigation

This repository contains the task code and map configurations used for a closed-loop first-person navigation experiment with large language models. At each step, the model receives a local egocentric observation represented as text, selects one navigation action, and receives the next observation generated by that action.

The release includes 60 maps and 180 fixed start-goal trials.

## Task overview

- Environment: 9 × 9 grid with flat, slope, and corner tiles.
- Observation: current position, orientation, locally visible tiles, tile properties, and directed adjacency.
- Partial observability: the complete map is never provided in the FPV condition.
- Initial orientation: `DOWN`.
- Maximum episode length: 100 steps by default.
- Actions: `MoveForward`, `MoveBackward`, `MoveLeftward`, `MoveRightward`, `TurnLeft`, and `TurnRight`.
- Movement cost: -1.0 per movement action.
- Turning cost: -0.2 per turning action.

Actions are relative to the agent's current orientation.

```text
├── requirements.txt

```

The map configuration is defined by:

- `selected_paths.json`: start and goal coordinates for every trial.
- `trap_lists.json`: trap tile IDs for every map.
- `annotations/<map_id>.json`: tile-level map annotation.
- `data.xml`: tile encoding metadata used by the map parser and visualization code.
- `experiments.json`: available baseline, ablation, and intervention conditions.

## Installation

Python 3.11 or later is recommended.

```bash
python3 -m venv ".venv"
source ".venv/bin/activate"
python3 -m pip install -r "requirements.txt"
```

## Validate the release

Check that all maps and task configuration files are present:

```bash
python3 "runner/validate_setup.py"
```

Expected summary:

```json
{
  "status": "ok",
  "maps": 60,
  "trials": 180,
  "annotations": 60
}
```

Validate a trial without calling an LLM endpoint:

```bash
python3 "runner/run_single_trial.py" \
  --model "dry-run-model" \
  --map 851 \
  --trial 2 \
  --repeat 0 \
  --experiment-type main_fpv_baseline \
  --condition omniscient \
  --output-dir "outputs/dry_run" \
  --dry-run
```

Run a short deterministic environment smoke test:

```bash
python3 "runner/run_single_trial.py" \
  --model "local-policy" \
  --map 851 \
  --trial 2 \
  --repeat 0 \
  --experiment-type main_fpv_baseline \
  --condition omniscient \
  --output-dir "outputs/local_smoke" \
  --local-policy \
  --max-steps 3
```

## Run one LLM trial

Configure endpoint credentials in the shell or in a local `.env` file that is not committed to version control:

```bash
export LLM_API_BASE_URL="https://your-llm-endpoint.example/v1"
export LLM_API_KEY="set-locally"
export LLM_MODEL_NAME="your-model-id"
```

Then run:

```bash
python3 "runner/run_single_trial.py" \
  --model "$LLM_MODEL_NAME" \
  --map 851 \
  --trial 2 \
  --repeat 0 \
  --experiment-type main_fpv_baseline \
  --condition omniscient \
  --output-dir "outputs/map_851_trial_2_repeat_0"
```

The endpoint must provide a compatible `/chat/completions` interface.

## Output files

Each episode directory contains:

```text
output_dir/
├── run_status.json
├── result.json
├── step_01/
│   ├── prompt.txt
│   ├── raw.txt
│   └── attempt_01/
└── step_02/
```

`result.json` records the map and trial identifiers, observations, state-action history, trajectory, model-output parsing failures, token usage, success status, and accumulated action cost.

Model navigation failures are retained as valid trials. Network errors, timeouts, and incomplete responses are recorded separately in `run_status.json` as non-model failures.

## Prompt conditions

- `main_fpv_baseline` uses `LLM/prompts/prompt_template_v6.txt` and expects one action only.
- `cognitive_map_prompt` uses `LLM/prompts/cm_cot_legacy.txt` and expects a JSON response containing `action` and `updated_memory`.
- `goal_trap_memory` limits ordinary accumulated visibility to the current step and selectively retains landmark locations across steps.
- `intervention` uses the baseline task with an additional strategy cue.

The prompt files are part of the experimental specification and should not be changed when reproducing the reported experiments.

## Run complete experiment conditions

`runner/run_experiment.py` selects the correct task scope, prompt, and memory rule for each experiment.

### Main FPV baseline

```bash
python3 "runner/run_experiment.py" \
  --experiment-type main_fpv_baseline \
  --condition omniscient \
  --model "$LLM_MODEL_NAME" \
  --repeats 5 \
  --output-root "outputs"
```

### Cognitive-map prompt ablation

Available conditions are `none/cm_cot` and `goal_only/cm_cot`.

```bash
python3 "runner/run_experiment.py" \
  --experiment-type cognitive_map_prompt \
  --condition "none/cm_cot" \
  --model "$LLM_MODEL_NAME" \
  --repeats 1 \
  --output-root "outputs"
```

### Goal/trap-memory ablation

All four conditions use one-step ordinary observation memory. They differ only in information retained persistently across steps:

| Condition | Persistent goal | Persistent traps |
|---|---:|---:|
| `none` | No | No |
| `goal_only` | Yes | No |
| `trap_only` | No | Yes |
| `all` | Yes | Yes |

```bash
python3 "runner/run_experiment.py" \
  --experiment-type goal_trap_memory \
  --condition goal_only \
  --model "$LLM_MODEL_NAME" \
  --repeats 1 \
  --output-root "outputs"
```

### Strategy-cue intervention

Available conditions are:

- `none`
- `higher_elevation`
- `wider_exploration`
- `higher_elevation_wider_exploration`

Intervention hard sets are derived separately for each model from that model's baseline results. No fixed model-specific hard-set list is included in the repository.

For compatibility with the ablation and intervention runs used in the paper, cognitive-map, goal/trap-memory, and intervention conditions start facing `SOUTH`. The historical cognitive-map and intervention prompts use the `NORTH/SOUTH/WEST/EAST` vocabulary. The goal/trap-memory prompt retains its original `UP/DOWN/LEFT/RIGHT` wording while the recorded environment state starts at `SOUTH`; this historical convention is preserved intentionally. The main FPV runner starts facing `DOWN`.

```bash
python3 "runner/run_experiment.py" \
  --experiment-type intervention \
  --condition higher_elevation \
  --model "$LLM_MODEL_NAME" \
  --baseline-results "outputs/main_fpv_baseline/omniscient" \
  --hard-threshold 0.4 \
  --minimum-baseline-runs 5 \
  --repeats 5 \
  --output-root "outputs"
```

Following the definition in the paper, the runner groups baseline `result.json` files by map-trial and selects trials whose success rate is strictly below `--hard-threshold` (default: `0.4`), provided that at least `--minimum-baseline-runs` valid results are available. A map-trial with success rate exactly `0.4` is not included. If a baseline directory contains multiple model IDs, specify the intended model with `--baseline-model`.

Alternatively, provide a model-specific CSV or JSON task list with `--task-file`. Each row must contain `map_id` and `trial`.

Add `--dry-run` to any command to inspect the dynamically selected tasks and prompt without calling the model. Use `--limit 1` for a single-task smoke test.

## Notes on reported cost

The saved `accumulated_cost` is the sum of movement and turning costs. It does not add a terminal goal reward.
